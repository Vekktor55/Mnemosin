# ROADMAP — «МНЕМОСИН» v3: три этапа, каждый — работающий MVP

Версия 1.0 · 2026-10-09
Основание: `МНЕМОСИН Pipeline v3` (baseline) + `MNEMOSIN_v3_AUDIT.md` (113 дефектов, 12 блокеров) + формат планирования v1 (`SPEC.md` / `ARCHITECTURE.md` / `DEV_PLAN.md`).

**Формат плана взят из v1 без изменений:** каждый этап имеет собственный набор **нумерованных критериев приёмки** (A<этап>.<номер>), каждый промпт самодостаточен и вставляется в отдельную сессию разработки, сервер поднимается в первом промпте и дальше каждый слой проверяется на живом процессе, все решения фиксируются в логе `D101+`, внешние провайдеры заменяются офлайн-стендами так, чтобы **весь цикл прогонялся без ключей и без сети**.

---

## 0. Ответ на вопрос «можно ли разделить»

**Да, и делить нужно ровно по границе портов.** v3 спроектирован как Ports & Adapters, а значит разрез «ядро → провайдеры» не требует переписывания: каждый следующий этап **добавляет** адаптеры и модули, а не меняет предыдущие.

| Этап  | Название                     | Что это для пользователя                                                                                                                                                                             | Промптов | Критериев | Оценка (1 разработчик + AI) |
| ----- | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------- | --------------------------- |
| **1** | **Стол** (`Table MVP`)       | Играбельная партия 6 игроков + GM: чат, действия, ход, черновик, ревью GM, коммит, перемещение по локациям. **Без внешних AI и без ComfyUI — работает офлайн**                                       | 13       | 16        | 3–4 недели                  |
| **2** | **Мир и AI** (`Product MVP`) | Настоящий AI Director (OpenRouter/LMStudio), Event Engine DSL, Rules Engine, world-pack «Ресепшн → Коридор → Комната с куклами», изображения (Debug → ComfyUI через HostBridge). **Это уже продукт** | 16       | 16        | 3–4 недели                  |
| **3** | **Прод и расширяемость**     | Snapshot/recovery, метрики и алерты, бюджеты, security-харденинг, multi-tab, **Audio Director как доказательство расширяемости**, perf-бюджет, деплой                                                | 14       | 8         | 2–3 недели                  |

**Итого 43 промпта, 40 критериев приёмки.**

### Ключевой принцип разреза (почему это не «переделывание заново»)

```text
ЭТАП 1 ─── ядро + транспорт + приватность + порт AIPort (стенд)
              │  100 % кода переиспользуется
              ▼
ЭТАП 2 ─── + адаптеры AIPort (OpenRouter/LMStudio)   ← новый код, ядро не трогается
           + Event Engine / Rules Engine (заглушки из этапа 1 → реализация)
           + MediaProvider (Debug/ComfyUI) + HostBridge
              │  100 % кода переиспользуется
              ▼
ЭТАП 3 ─── + snapshot/metrics/budget/security + Audio Director (плагин)
```

Замена заглушки на реализацию — это **один файл адаптера + одна строка регистрации** в Capability Registry. Именно это проверяют критерии A1.14 и A3.5.

## 2. Этап 1 — «Стол» (Table MVP)

### 2.1 Что входит

Доменное ядро (Session, Player, Character, Turn, PlayerAction, GameState-minimal, LocationDefinition), машина состояний Turn, идемпотентность, журнал хода, outbox, optimistic lock, SQLite+Drizzle, модули `session`/`chat`/`gm`/`gm-review`/`story`, порт `AIPort` **со стендовыми провайдерами**, Capability Registry с circuit breaker, Fastify HTTP + нативный WebSocket, проекции и приватность, Svelte-клиент (игрок + GM), e2e.

### 2.2 Что НЕ входит (осознанно)

| Не входит                                     | Почему безопасно отложить                                                                                                                     |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Реальные AI-провайдеры (OpenRouter, LMStudio) | `AIPort` уже реализован стендами; замена — один файл (A1.14)                                                                                  |
| Event Engine DSL (триггеры/условия/эффекты)   | В Turn Engine — точка расширения `applyEffects`, в этапе 1 пропускающая эффекты из черновика напрямую. DSL навешивается в 2.1 без правки ядра |
| Rules Engine                                  | В этапе 1 — `rulesStub`, возвращающий `PASS` на всё (интерфейс тот же, что в v3 §III.7)                                                       |
| ComfyUI / Media / HostBridge                  | Модуль `media-director` не зарегистрирован; `CAPABILITY_CHANGED` уже умеет сообщать «нет провайдера»                                          |
| Snapshot-восстановление                       | Этап 1 восстанавливается из SQLite (это уже полная персистентность, A1.11); snapshot-механизм — UNKNOWN#6, закрывается в 3.1                  |
| Метрики/бюджеты/алерты                        | Структурированные логи с `traceId` есть с промпта 1.1; prom-экспорт — 3.2                                                                     |
| Multi-tab, perf-тесты                         | 3.4, 3.6                                                                                                                                      |

### 2.3 Критерии приёмки A1 (проверяются на живом сервере)

| #         | Критерий                                                                                                                                                                                                                                                                          |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A1.1**  | `npm run dev` поднимает сервер; `GET /health` → `{ok:true, version, capabilities}`; при отсутствии обязательной env-переменной процесс завершается с внятным сообщением **без значения секрета**                                                                                  |
| **A1.2**  | Architecture-тест зелёный: `core/` не импортирует `infrastructure/`, `modules/`, `gateways/`, `client/`, `fastify`, `drizzle-orm`, провайдерские SDK                                                                                                                              |
| **A1.3**  | Каждое WS-сообщение и каждый HTTP-body проходят Zod-парсинг; сообщение неизвестного типа → `ERROR{code:'VALIDATION'}`, соединение не рвётся                                                                                                                                       |
| **A1.4**  | **Идемпотентность:** повторный `POST /turns/:id/commit` с тем же `idempotencyKey` возвращает тот же `version`, второй записи в `turn_journal` нет, состояние не меняется; два параллельных запроса с одним ключом → один проходит, второй получает `409 IDEMPOTENCY_IN_FLIGHT`    |
| **A1.5**  | **Optimistic lock:** две параллельные записи GameState → вторая получает `VERSION_CONFLICT`, версия увеличивается ровно на 1                                                                                                                                                      |
| **A1.6**  | **Машина состояний Turn:** разрешены только переходы из таблицы v3 §II.5; запрещённый переход → `409 CORE_INVALID_STATE_TRANSITION`; полный путь `OPEN→LOCKED→PROCESSING→REVIEW→COMMITTED` проходит                                                                               |
| **A1.7**  | **Приватность:** property-based тест на всех broadcast-сообщениях — `privateMessages`, заметки `GM_ONLY`/`AI_DIRECTOR`, чужой `playerKnowledge` не встречаются ни в одном envelope, уходящем не адресату; `GET /state/projection?view=ai                                          | gm`с токеном игрока →`403` |
| **A1.8**  | **Цикл GM Review:** `TURN_DRAFT_READY` приходит только GM; `editAndApprove` с `baseResolutionHash` увеличивает `version`; повтор с устаревшим хэшем → `409`; `reject` → `TURN_FAILED` с `errorCode`                                                                               |
| **A1.9**  | **Реконнект:** `kill -9` сервера во время партии → клиент уходит в `RECONNECTING`, после подъёма получает `AUTH_OK` → `STATE_PROJECTION` → `TURN_UPDATE`; оптимистичные сообщения, не получившие ack, доставляются ровно один раз                                                 |
| **A1.10** | **Чат:** публичные видны всем, приватные — только адресату, системные/GM — по видимости; порядок по `sequence_id`; `GET /chat/history?since=` совпадает с кольцевым буфером клиента (500)                                                                                         |
| **A1.11** | **Персистентность:** после рестарта сервера восстанавливаются сессия, игроки, текущий ход, GameState (version), чат, журнал; незакоммиченный `PROCESSING`-ход переходит в согласованное состояние по правилам `reconcileOnBoot`                                                   |
| **A1.12** | **AI-стенды:** переключением env работают `ScriptedAI` (детерминированный JSON из фикстуры), `EchoAI` (нарратив из действий игроков), `FailingAI` (`PROVIDER_TIMEOUT`) — **без изменения кода ядра и модулей**; при `FailingAI` ход → `FAILED`, GM может retry, игра продолжается |
| **A1.13** | **Capability Registry:** circuit breaker размыкается после `failureThreshold`, публикует `CAPABILITY_CHANGED{available:false}`; `resolve()` возвращает цепочку fallback из `capabilities.yaml`; `/health` отражает состояние                                                      |
| **A1.14** | **Тест расширяемости:** добавление провайдера `FailingAI` (и любого нового) = 1 файл адаптера + 1 строка в конфиге; architecture-тест запрещает адаптеру импортировать `core/`                                                                                                    |
| **A1.15** | **Локации и перемещение:** `gm.moveGroup` меняет `worldState.currentLocationId`, эмитит `LOCATION_CHANGED`, клиенты получают обновление проекции; перемещение в несуществующую локацию → `CORE_LOCATION_NOT_FOUND`; выход с `locked:true` → `RULE_REJECTED`                       |
| **A1.16** | **E2E-сценарий «Стол»:** Playwright прогоняет: создание сессии → 6 игроков join → действия → lock → черновик (ScriptedAI) → правка GM → commit → нарратив у всех → приватное сообщение только адресату → moveGroup в Corridor → ход №2. Все A1.1–A1.15 зелёные в CI               |

## 3. Этап 2 — «Мир и AI» (Product MVP)

### 3.1 Что добавляется

Event Engine DSL (Trigger/Condition/Effect + `FIRST_TIME` + приоритеты + каскад + deferred), Rules Engine (bundle, short-circuit, `SOFT_REJECT → requiresGM`), **world-pack** (шаблоны slug → инстанцирование в UUID), контент Reception/Corridor/DollRoom, `DirectorContext` builder, **OpenRouter** и **LMStudio** адаптеры, prompt repair, cost model и бюджет, `VisualPromptProvider`, **Media Director** + `DebugMediaProvider` + `media_cache`, **ComfyUI через HostBridge** (HMAC + replay-защита).

### 3.2 Критерии приёмки A2

| #         | Критерий                                                                                                                                                                                                                                                                     |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A2.1**  | `DirectorContext` собирается из проекции, проходит `DirectorContextSchema`; **golden-тест** фиксирует состав; `allowedEventIds` содержит только зарегистрированные события; GM-only заметки не попадают в контекст при `visibility=GM_ONLY`                                  |
| **A2.2**  | OpenRouter возвращает валидный `AIResponse` по схеме; «грязный» JSON → 1 попытка prompt repair → `PROVIDER_SCHEMA`; ключ отсутствует только в env, в логах и в WS не появляется (grep-тест)                                                                                  |
| **A2.3**  | При отказе OpenRouter срабатывает fallback на LMStudio; при отказе обоих — `TURN_FAILED{PROVIDER_UNAVAILABLE}`, breaker open, `CAPABILITY_CHANGED{false}`                                                                                                                    |
| **A2.4**  | В `turn_journal` и в `resolution.diagnostics` фиксируются `input/output tokens`, `model`, `provider`, `durationMs`, `costUsd`; `ai.cost_usd_total` растёт                                                                                                                    |

| **A2.7**  | World-pack: slug-ID шаблонов инстанцируются в UUID с таблицей remap; все `exits`/`objects`/`registeredEventIds` ссылаются на существующие сущности сессии; валидатор pack'а зелёный на Reception/Corridor/DollRoom                                                           |

| **A2.9**  | Медиа-джоба: `QUEUED → SUBMITTED → READY/FAILED`; не более `mediaMaxConcurrentPerSession` одновременно; `media.queue_depth` отражает очередь                                                                                                                                 |
| **A2.10** | Кэш по `(prompt_hash, provider, workflow, seed)`: повторный запрос той же сцены не вызывает провайдера, возвращает сохранённый файл                                                                                                                                          |
| **A2.11** | `DebugMediaProvider` всегда доступен: без ComfyUI игра продолжает идти, `MEDIA_READY` приходит с placeholder-изображением                                                                                                                                                    |
| **A2.12** | ComfyUI через HostBridge: `HB_JOB_SUBMIT` → `HB_JOB_RESULT` → `MEDIA_READY` с реальным изображением; ComfyUI выключена → fallback на Debug без влияния на ход                                                                                                                |
