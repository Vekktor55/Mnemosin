## Принятые решения (2026-10-09)

- **D102** — Fastify + `@fastify/websocket` (нативный WS, не Socket.io).
- **D103** — Svelte 5 + Vite.
- **D108** — одна активная сессия на сервер (закрывает `UNKNOWN#9` v3; схема БД остаётся session-scoped).

Остальные D101–D112 — в `ROADMAP.md` §8; принимаемые по ходу реализации — D113+ в `docs/ARCHITECTURE.md` (создаётся промптом 1.1).

## Как работать с планом

1. Открыть `DEV_PLAN_STAGE1.md`, скопировать текст промпта 1.1 (блок, ограниченный четырьмя обратными кавычками) в новую сессию разработки.
2. Проверить результат по разделу «Проверка» внутри промпта и по критериям A1 из шапки.
3. Принятые решения занести в `docs/ARCHITECTURE.md` (D113+).
4. Следующий промпт — в **новой** сессии (промпты самодостаточны).
5. После промпта 1.13 → `node tools/verify/stage1.mjs` должен дать **16/16 PASS** → Gate 1 → сверка `DEV_PLAN_STAGE2.md` с кодом (v1.0 → v1.1) → этап 2.

## Сквозные принципы (унаследованы от формата v1)

- Сервер стартует в первом промпте; каждый слой проверяется на живом процессе.
- Внешние зависимости заменены офлайн-стендами (`ScriptedAI`/`EchoAI`/`FailingAI`, `lmstudio-stub`, `DebugMediaProvider`, `host-agent` в stub-режиме) → **весь прогон без ключей и без сети**.
- Не хватает данных или решения — реализатор останавливается и спрашивает, не изобретает.
- Источник истины — код (`@mnemosin/contracts`), документация генерируется из него и проверяется в CI (`docs:check`).
- Каждый промпт заканчивается проверкой; критерий приёмки = наблюдаемое поведение, а не «модуль написан».
