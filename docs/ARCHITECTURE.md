# ARCHITECTURE — «МНЕМОСИН» (v4 baseline)

**Статус:** миграция v4 в процессе. Целевая архитектура и инварианты — `docs/SYSTEM_ARCHITECTURE.md`.

**Назначение файла:** журнал инженерных решений (D\*) текущей ветки. Исторический журнал v3
(D101–D293) сохранён в истории git (`ac53780^:docs/ARCHITECTURE.md`) и **не является** актуальным
источником требований.

**Правила изменения `core/`** (критерии A1.14, A3.5): изменение файлов `core/` допустимо только
как осознанное архитектурное решение. Порядок: (1) запись D\* здесь с обоснованием «почему это
нельзя было сделать модулем или адаптером»; (2) `npm run arch:manifest`;
(3) `tests/arch/core-manifest.test.ts` должен пройти.

## 1. Лог решений

### 1.1 Решения, принятые при миграции v4 (P02–P03)

| #        | Вопрос                                                                    | Решение                                                                                                                                                                                                                                                                                                                              | Следствие для кода                                                                                                                                                                |
| -------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D294** | Где живёт валидация World Pack: в core, отдельном модуле или адаптере?    | **В core.** Zod-схема `SpatialWorldPackSchema` — в `@mnemosin/contracts` (leaf-пакет, D112). До правки расхождение `\` vs `/` давало ложный провал `core-manifest.test.ts` и `extensibility.test.ts`.                |

**Обоснование D294 (развёрнуто).**

- **Что здесь доменное, а что — адаптер.** JSON-разбор и схема — граница формата (`contracts`).
  Проверка ссылочной целостности, границ и проходимости — **доменное правило серверной геометрии**
  (`docs/WORLD_SIMULATION.md` §3.6: validator обязан проверять уникальность ID, корректность
  клеток/порталов, spawn points до запуска партии). Оно не зависит от БД, транспорта, рендера и
  поэтому не является адаптером.
- **Почему не модуль.** Модули зависят от `contracts` и портов `core`, но не наоборот
  (`SYSTEM_ARCHITECTURE.md` §17.3, D161). Валидатор нужен самому ядру уже в P04 (HOT-симуляция
  применяет геометрию), т.е. до и независимо от игровых модулей; размещение в модуле создало бы
  обратную зависимость ядро→модуль.
- **Почему не infrastructure-адаптер.** Адаптер реализует порт и/или говорит с внешней системой
  (БД, сеть, ФС). Здесь внешнего протокола нет — есть чистая функция над контрактом; вынос в
  infrastructure сделал бы доменное правило зависимым от слоя, которому оно не принадлежит.
- **Граница I/O соблюдена.** `node:fs` в `core/` отсутствует: `parseWorldPack(jsonText)` — чистая
  функция, чтение файла остаётся в wiring (D221, `WorldPackData` инъектируется).

### 1.2 Решения, принятые в P04

| #        | Вопрос                                                           | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Следствие для кода                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D296** | Где живут HOT clock, authoritative movement и collision queries? | **В изолированной подсистеме `core/src/hot/`.** Чистый `runHotSimulationStep` получает состояние, упорядоченные входы, геометрию и prototype-конфигурацию; `HotRuntime` отдельно принимает/валидирует сообщения, а `HotTickScheduler` отдельно управляет accumulator-based запуском. Часы и таймеры инъецируются; WebSocket, Fastify, PixiJS, SQLite и файловый I/O в Core запрещены прежними границами. Игроки обрабатываются по `participantId`, входы — по серверному `arrivalSequence`; player body-block не вводится (WS-04 остаётся PROTOTYPE-ONLY: игроки проходят друг через друга). | `core/` планово расширен HOT-подсистемой и barrel-экспортом. Скорость, радиус, epsilon и input lease передаются конфигурацией и не становятся сетевыми полями или каноном. Связанный с edge portal определяет проходимость двери: `open` — проходимо, `closed`/`locked` — блокирует; `door` без `initialState` требует явной начальной runtime-проекции состояния вместо догадки. Манифест перегенерирован после реализации. |

**Обоснование D296 (развёрнуто).** HOT-симуляция — доменное вычисление над контрактами World Pack и spatial input; она нужна серверному ядру независимо от конкретного транспорта и не реализует внешний порт. Вынос в модуль создал бы зависимость Core от игрового модуля либо обратный импорт при повторном использовании collision rules, а вынос в infrastructure ошибочно связал бы чистую геометрию с адаптером. Поэтому Core содержит только вычисления и абстрактные часы/таймеры; реальная сетевая привязка и replication остаются отдельным этапом P05.

### 1.3 Решения, принятые в P05-A

| #        | Вопрос                                                                                                      | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Следствие для кода                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D297** | Где связываются P04 `HotRuntime`/`HotTickScheduler`, WebSocket gateway, authentication и scene replication? | **В composition root `apps/server`; Gateway получает только структурные порты.** P04-классы остаются в `core/src/hot/` и не знают о Fastify/WebSocket. `apps/server/src/hot-wiring.ts` создаёт единственный authoritative `HotRuntime` и `HotTickScheduler` с монотонными `performance.now()` и реальными timers; `gateways/ws` маршрутизирует `scene:input`, публикует ACK и строит role-specific projection перед сериализацией. Handshake `mnemosin.v1.<jwt>` и server-owned `ConnectionActorContext` сохранены. Каждый reconnect создаёт новый `connectionEpoch` и `inputStreamId`, сбрасывает старый HOT input stream и выдаёт свежий keyframe; старые movement inputs не replay'ятся. | Изменения ограничены `apps/server` и `gateways/ws`; `core/` не менялся, поэтому `core-manifest.json` не потребовал D297-регенерации. Legacy `WsTurnOps`/`WsGmOps`/`WsGmReviewOps` и Turn/GM WS handlers удалены; старый v3 client catalog сохранён только как compile-time compatibility alias до P05-B и серверным gateway не используется. Scene delivery коалесцирует только совместимые deltas, сохраняет reliable FIFO и при разрыве base-chain переходит к keyframe/resync. Gateway ограничивает pending+active sockets по socket remote IP (X-Forwarded-For не доверен без proxy allowlist), применяет configured auth deadline и supervisor'ом с отдельным 50 ms cadence возобновляет P04 scheduler после controlled backlog pause без изменения Core; heartbeat не управляет скоростью восстановления. |

**Обоснование D297 (развёрнуто).** P04 уже отделил чистую симуляцию от внешнего ingress и планировщика, но не определил, кто создаёт эти компоненты и как WS-транспорт получает authoritative state. Прямой импорт `HotRuntime` в `gateways/ws` нарушил бы запрет транспорта на владение игровым runtime и создал бы зависимость gateway от конкретной формы Core. Composition root `apps/server` уже является единственным server wiring слоем; создание runtime там сохраняет одного владельца состояния, а структурные порты (`WsHotMatchPort`, `WsHotRuntimePort`, `WsHotSchedulerPort`) оставляют Gateway трансортным и privacy-aware слоем. Authentication и actor context также формируются только сервером из JWT/session membership, поэтому клиент не может назначить себе role, permissions или controlling stream. Scene replication строится из отдельных Player/Observer DTO до JSON-сериализации; reliable lifecycle/ACK/keyframe сообщения не вытесняются coalescing временных delta. Это решение не изменяет Core и не закрывает открытые NET-01…NET-20: численные значения остаются `PROTOTYPE-ONLY`, а handshake остаётся текущим до отдельного решения владельца.
